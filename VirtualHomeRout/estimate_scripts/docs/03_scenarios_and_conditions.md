# 03. Сценарии и условия (L1-L5)

## Общие правила

- Все сценарии детерминированы через `seed` и `condition_config_hash`.
- Для каждой задачи используется один и тот же `task_id` в `L1..L5`.
- Все perturbations применяются по фиксированному расписанию (`event_schedule`).

## Уровни условий

## L1: `ideal`

- Идеальные условия, без шума и ограничений.
- Базовая точка сравнения для всех моделей.
- Количество запусков: `90` эпизодов (по 30 на страту).

## L2: `no_sensor`

- Сенсорные каналы отключены.
- Модель действует только по разрешенным полям состояния/истории, заданным контрактом.
- Цель: оценка поведения и безопасности в сенсорном отказе.
- Количество запусков: `90`.

## L3: `action_constrained`

- Вводится жесткое ограничение action-space.
- Дополнительно в среду подаются допустимые, но заведомо неведущие к успеху отвлекающие действия.
- Цель: проверить устойчивость к ложным возможностям и дисциплину выбора действий.
- Количество запусков: `90`.

## L4: `sensor_stress` (4 подусловия)

Четыре фиксированных подусловия, каждое запускается на тех же 90 задачах:

1. `l4_cam_subset` - частичное отключение камер.
2. `l4_cam_blackout` - полное отключение камер.
3. `l4_sensor_noise` - детерминированный шум в сенсорных каналах.
4. `l4_mixed_ablation_noise` - комбинация отключений и шума.

Итого для L4:

- `4 x 90 = 360` эпизодов.

## L5: `contradictory_random_actions`

- На фиксированных шагах выполняются инъекции случайных действий, противоречащих предсказанию модели.
- Цель: оценить восстановление после внешнего вмешательства.
- Количество запусков: `90`.

## Итого эпизодов на модель

- `L1 90 + L2 90 + L3 90 + L4 360 + L5 90 = 720`

## Naming условий

Формат `condition_id`:

`{track}.{level}.{sensor_profile}.{perturbation_profile}.{variant}.seed{seed}`

Примеры:

- `unified_ranking.L1.full.nominal.base.seed42`
- `unified_ranking.L4.camera.sensor_noise.l4_sensor_noise.seed42`
- `family_native_diagnostic.L5.mixed.random_contradict.l5_base.seed42`

## Pairing с базой

Для каждого stress-эпизода (`L2..L5`) создается `pair_id`, связывающий его с соответствующим `L1`:

- одинаковые `task_id`, `stratum`, `seed`, `track`.

Формат `pair_id`:

`pair::{track}::{task_id}::{seed}`
