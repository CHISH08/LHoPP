# 01. Обзор протокола

## Цель

Создать единый, воспроизводимый и честный протокол сравнения long-horizon моделей в `VirtualHome` с исполнением строго через Unity.

## Границы этапа

- В области: только `VirtualHome` + Unity API.
- Вне области: CALVIN, обучение/дообучение, online-адаптация моделей между эпизодами.
- Оцениваем только запуск (inference/execution), без изменения весов моделей.

## Fairness-контракт

Для всех сравниваемых моделей должны совпадать:

- список эпизодов (`task_id`, `seed`, `condition_id`);
- бюджеты (`max_steps`, `max_time_sec`);
- определение успеха (`success oracle`);
- интерфейс допустимого действия (единый action contract);
- правила маскировки сенсоров и инъекций perturbations.

Запрещено в benchmark-run:

- дообучение;
- изменение prompt/adapter на лету по итогам других эпизодов;
- перенос скрытого состояния между эпизодами (по умолчанию reset состояния модели перед каждым эпизодом).

## Два трека сравнения

## `unified_ranking`

Главный трек для межсемейного сравнения.  
Все модели получают одинаковый минимальный интерфейс наблюдений и одинаковые ограничения.

## `family_native_diagnostic`

Диагностический трек внутри семейства.  
Разрешены дополнительные нативные сигналы, но результаты не используются для главного межсемейного ранжирования.

## Стабильные сущности

- `episode_id` - уникален для эпизода.
- `condition_id` - уникален для условия.
- `pair_id` - связывает эпизоды `L1` и stress-эпизоды для той же задачи/seed.
- `manifest_hash` - подтверждает, что входы и условия идентичны для всех моделей.
